# Agent workflow

Fission is a tool for the user's existing agent. It does not decide when an issue is solved. Keep all work in this repository; runtime state, wallet credentials and experiment records belong outside it.

1. Run `fission capabilities` and `fission list --json`. Match the issue to an explicit profile and its hard requirements. Never silently substitute a runtime sandbox for a full VM, P2P, or a guaranteed-size build. `plan` returns `status: unavailable` and exit 2 before any quote/payment when requirements cannot be met.
2. Record the user's aggregate authorization with `budget --total-spend AMOUNT --approve`. This ledger applies across CLI invocations sharing `FISSION_HOME`. It cannot be reset or increased by repeating the command. Do not change state directories to evade an authorization. Amounts cover gateway charges; leave room in the user's overall budget for network fees.
3. Create `plan NAME --recipe RECIPE --duration DURATION --max-spend CREATION_CAP --total-spend TOTAL_CAP`. Optional `--profile`, `--cpu`, `--memory` (GiB), `--disk` (GiB), `--arch`, `--os`, and `--kind` express requirements. Resource floors are planning estimates, not measured workload performance guarantees. Runtime recipes explicitly have no reserved capacity. Leave enough total budget for commands, observations, artifact transfer, and shutdown.
4. For public source, pass `--repo https://github.com/OWNER/REPO --ref FULL_COMMIT`. Resolve the intended PR head to its 40-character SHA first. The remote checkout verifies HEAD and records submodule revisions. Private source is uploaded explicitly; never transfer GitHub or wallet credentials. Source checkout does not imply compiling the client.
5. Review the saved plan and call `open NAME --plan ID --approve` within the user's authorization. This purchases once and submits the `bootstrap` job. Observe with `job NAME bootstrap --refresh` or `wait NAME bootstrap --duration 5m --max-spend 0.01`. Provider running is not workload readiness. Wait exit 2 means its observation budget/time ended; the remote job may continue. Exit 1 means failure or an error. Inspect the returned phase.
6. Submit ordinary work with `run NAME JOB --duration DURATION -- COMMAND ARG...`. The guest supervisor bounds the foreground process group. Detached services started by a command can outlive that job and remain bounded by the workspace lease. Jobs run in `/workspace`; executables are at `/workspace/forge`, `/workspace/reth`, or `/workspace/tempo`. Use argv directly; use an explicit shell only when shell semantics are wanted. A job name is never reused, including after an ambiguous launch. `jobs NAME` lists saved job IDs locally. `job --refresh` observes its existing marker and never re-executes the command. Unknown is not failed and must not trigger a new equivalent job automatically.
7. Retrieve the job's returned `log` path and explicit outputs with `download NAME /remote/file NEW_LOCAL_FILE`. Individual modest files only. Stop writers before export; a changing file fails checksum validation. `close NAME --output NEW_DIR` exports the recipe's declared files plus bootstrap output, then terminates. It does not collect arbitrary job outputs. If no files are needed, use `--discard-output`. Close when the user considers the issue done, independently of PR state. A termination acknowledgement is followed by a status check; `termination_unknown` requires later observation before reporting cleanup complete.

## Recovery and limits

For the simplest VM flow, use `plan NAME --recipe foundry --cheapest --budget AMOUNT --region ams --duration 24h`. `--budget` replaces both spending caps; do not combine them. It is the requested whole-workspace gateway allocation, not aggregate authorization or a fees-inclusive wallet-spend guarantee. Planning preserves that allocation and caps creation at the actual final quote. At least 0.0003 remains as the existing lifecycle accounting floor; this does not estimate all future calls or exports. `--cheapest` requires this budget mode, an explicit 24-hour lease and region, and cannot be combined with a specific machine or an incompatible provider/kind. It selects the lowest successful quote in the capped shortlist, never a guaranteed global minimum. A changed quote fails; open never reselects. Plan JSON returns `paymentSubmitted: false` and executable `open` argv. Use those only within the user's existing authorization. The task itself is an explicit subsequent `run`; bootstrap success does not establish task completion.

The plan's `funding` object exposes validated Tempo chain/token identity, creation amount, allocation and remaining allocation. Network fees are excluded; wallet balance and funding shortfall are unknown. An agent can preview an existing authorized Glue Tempo-token refill policy using its returned argv (replace the policy placeholder). Use Glue's payment-token mode for USDC.e, not native-gas prepared transactions. A new Glue target, swap input cap, cumulative swap budget, fee reserve or grant needs its own authorization; a VM quote supplies none of these. Fission neither runs Glue nor installs or changes its policies.

For VMs, configure `budget --vm-max-spend AMOUNT --approve` within the aggregate authorization. An optional `--profile PROFILE` ceiling and explicit discovery cap only narrow the global ceiling. Changing a ceiling requires user/operator authorization; an average is never permission to increase it. The ceiling bounds the entire workspace allocation, including creation and lifecycle headroom. It is rechecked on plan, open and payment reservation.

Run `machines --profile PROFILE --region ams --duration 24h` to dry-quote up to three cheapest compatible catalog plans under the ceiling. The mean, range and sample count describe that capped shortlist from one provider, not a market average. Empty results retain the hardware and spending requirements; never increase the cap or shrink the disk just to get an offer. CPU units are provider vCPUs; decimal disk GB are converted to GiB conservatively.

Select a returned machine with `plan NAME --provider x402-compute --machine MACHINE --region REGION --duration 24h` plus the ordinary recipe/profile/budget flags. Explicit compute selection defaults to VM; an explicit incompatible kind is rejected. This backend uses Vultr Ubuntu 24.04 x64, a workspace-specific SSH key and a one-time management credential saved privately in the state directory. Never expose or commit these credentials. There is no automatic renewal or refund promise. Small-VM execution, detached jobs, deadline enforcement, file export and authenticated destruction have been observed; large disks and public P2P have not been exercised. Catalog matching is not a synced-node readiness claim.

If SSH provisioning ends before a bootstrap job is recorded, observe the same workspace and run `prepare NAME` explicitly to resume. Once bootstrap has been recorded, only observe it; never replay preparation or purchase. After a failed deletion acknowledgement, close makes one status observation; unresolved outcomes remain `termination_unknown`.

A VM ceiling, missing aggregate authorization or exhausted aggregate allocation rejected at the locked reservation boundary records `not_submitted`. No provider request escaped; a new plan within the existing authorization may reuse that name. This exception never applies to genuinely ambiguous paid requests.

`ui` opens the local terminal interface: arrows select, Enter shows details, Tab filters, and `s` sorts. Enter from a ready VM's detail opens SSH and returns to the interface on disconnect. `x` saves declared output and closes after a local confirmation; it does not save arbitrary job outputs. SSH credentials remain local, with agent forwarding disabled. `ssh NAME` provides the same interactive connection without the TUI. Agents should use the JSON commands rather than automate terminal keys.

`spending` reads saved transaction references and cached verified amounts. `spending --refresh` or `v` in the TUI makes free, read-only Tempo RPC queries. Amounts represent verified sender USDC.e outflow, including fees in that token; other assets and later refunds are excluded. Transactions are deduplicated globally. Missing or unreadable receipts remain unknown, and a shared transaction is not assigned in full to each workspace. These payment figures never replace the conservative authorization ledger. The TUI reloads local state only; `p` explicitly checks the selected provider using its existing request cap. Quitting does not terminate machines.

`list`, `status` and `watch` show cached observations. `status --refresh` checks the provider; `job --refresh` checks the workload. `watch --refresh --max-spend AMOUNT` polls within a separate foreground cap and the durable workspace allocation. Ctrl-C stops observing; provider expiry still applies. Remote job completion does not mean the machine is terminated.

Preserve unresolved records and call `reconcile NAME` to recover a saved creation response and observe the provider. It never repeats creation or bootstrap. A missing remote ID needs provider/payment investigation. A launch marker without a running/completed supervisor remains unknown. Check a stale operation lock's PID before removing only that lock after its process exits. Never discard receipts to retry payment.

Budget reservations retain the full request cap even when a call fails. They are conservative bounds, not a report of actual spend. Workspace allocations remain allocated after close. Two operation caps remain for termination/status; artifact retrieval needs additional room. A failed export does not stop provider expiry.

The `output.log` artifact basename is reserved for saved-plan bootstrap output. Custom JSON recipes contain `name`, optional `description`, `prepare` argv arrays, `artifacts` absolute remote file paths, and optional `readiness` argv arrays. Saved-plan bootstrap executes preparation once; readiness repeats every 15 seconds inside its deadline until every command exits zero. Keep probes read-only and bounded. Legacy `open --recipe` retains synchronous preparation and a creation-only cap; use saved plans for the agent workflow.

`reth` is a private local development chain. A synced execution/consensus workload requires a compatible pinned snapshot, expansion and growth capacity, matching network/genesis, Engine API JWT, execution and consensus P2P, and readiness at a fresh head. `harness/ethereum-ready.py` is an observer for an already configured pair, not a deployment recipe. It accepts explicit chain ID and maximum head age and rejects optimistic/offline consensus. The `reth-synced` profile retains at least 32 GiB RAM and 2048 GiB disk; check current snapshot expansion, consensus storage and growth before raising the floor for an issue. No affordable synced deployment has been verified.

Tempo's recipe starts an isolated development chain at loopback port 8645. Its local block producer is not Tempo's production consensus network. Source profiles select hardware floors; a source checkout still requires explicit toolchain setup and compilation. No automatic public-network transactions, validator enrollment, or vulnerability reproduction workflow is provided.
